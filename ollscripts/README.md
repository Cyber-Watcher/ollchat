# ollscripts — обслуживание Ollama на сервере

## ollmanageubuntu.sh

Установка, обновление и удаление Ollama на Ubuntu. Запускается через `sudo`
на самом сервере.

```bash
sudo ./ollmanageubuntu.sh                    # поставить, а если стоит — обновить
sudo ./ollmanageubuntu.sh -del               # удалить, сохранив конфиги и модели
sudo ./ollmanageubuntu.sh -restore КАТАЛОГ   # вернуть конфиги из копии
./ollmanageubuntu.sh -h                      # справка
```

Ключ `-y` отключает вопросы — нужен при запуске по ssh без терминала.

Рабочая копия лежит на стенде: `/home/admin/bin/ollmanageubuntu.sh`.
Исходник здесь; при доработке заменяйте копию на сервере целиком и сверяйте
`sha256sum`.

### Что скрипт делает

* **Без ключей.** Нет Ollama — ставит последнюю выпущенную версию. Есть —
  сверяет с последней и обновляет, если есть что обновлять. Повторный запуск
  на свежей версии ничего не делает и так и говорит.
* **Драйверы.** Перед установкой проверяет NVIDIA: если карта есть, а рабочего
  драйвера нет, ставит рекомендованный через `ubuntu-drivers install` и
  предупреждает, что нужна перезагрузка.
* **Служба.** Ставит Ollama службой systemd с автозапуском, после установки
  печатает, где лежат настройки и как службой управлять.
* **Удаление.** Пакетную установку сносит через `apt purge`, ручную — файлами.
  Перед этим снимает резервную копию настроек.

### Три вещи, которые скрипт бережёт

1. **Каталог моделей не трогает никогда.** На стенде это 127 ГиБ; выкачивать
   заново — часы. Удаление сносит программу, но не данные.
2. **Системного пользователя `ollama` не удаляет.** Каталог моделей принадлежит
   ему по uid; удалить пользователя — осиротить 127 ГиБ по правам доступа.
   При установке скрипт наоборот проверяет владельца и выправляет его.
3. **Настройки сохраняет и возвращает.** Перед удалением копирует unit-файл,
   `override.conf`, `/etc/default/ollama` и манифест (версия, пути, переменные,
   список моделей) в `~/ollobackups/ГГГГ-ММ-ДД_ЧЧ_ММ` того пользователя, который
   запустил `sudo` — не root. При следующей установке предлагает вернуть
   переопределения оттуда: без них потеряется `OLLAMA_HOST`, и сервер станет
   слушать только себя.

### Чего скрипт не умеет

* Ветка удаления через `apt` написана, но **не проверена**: официального
  пакета Ollama в репозиториях нет, а на стенде установка ручная.
* Установка драйверов не проверена: на стенде драйвер 595.84 уже стоял,
  и скрипт правильно это увидел и ничего не делал.

## searxngmanage.sh — поисковик для web_search

Ставит SearXNG контейнером и заводит службу systemd. Нужен инструменту `web_search`: публичные
поисковики запросы от программ отклоняют (DuckDuckGo отдаёт заглушку со второго запроса, публичные
экземпляры SearXNG — 403 и 429), поэтому нужен свой.

```bash
sudo ./searxngmanage.sh              поставить, а если стоит — обновить образ
sudo ./searxngmanage.sh -del         удалить, сохранив настройки
sudo ./searxngmanage.sh -restore КАТАЛОГ
sudo ./searxngmanage.sh -p 8080      другой порт (по умолчанию 8888)
```

Что делает установка:

1. кладёт `settings.yml` в `/opt/searxng` — главное там `search.formats: [html, json]`,
   без этой строки наружу идёт только HTML и `web_search` получит вёрстку вместо данных;
2. заводит `docker-compose.yml` и службу `searxng`;
3. загружает образ, запускает, **проверяет, что JSON действительно отдаётся**;
4. печатает готовую строку для конфига ollchat.

Ставится туда, где запущен: на сервер — через `scp` и `ssh`, локально — прямо из каталога проекта
(нужен `sudo apt install docker.io docker-compose-v2`, если Docker ещё не стоит).

**Про `secret_key`.** Скрипт создаёт его при первой установке и при обновлении берёт из прежних
настроек, а не создаёт заново. SearXNG подписывает им cookie с настройками пользователя, ссылки
на картинки и значки сайтов через встроенный прокси (HMAC-SHA256) и использует как пароль к кэшу.
Для работы ollchat это почти безразлично — мы ходим в JSON API без cookie, прокси картинок
выключен, — но у тех, кто открывал поисковик браузером, смена ключа сбрасывает настройки
и ломает ранее выданные ссылки на картинки.

Правила те же, что у `ollmanageubuntu.sh`: настройки не теряются. Перед изменением они копируются
в `~/searxngbackups/ГГГГММДД-ЧЧММСС` того, кто запустил `sudo`, а секретный ключ подписи при
обновлении берётся из прежних настроек — иначе разойдутся уже выданные ссылки.

Проверить вручную:

```bash
curl -s 'http://СЕРВЕР:8888/search?q=golang&format=json' | head -c 200
```
