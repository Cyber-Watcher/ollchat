# ollnode — наблюдатель на сервере Ollama

Маленькая служба, которая работает **на той же машине, что и Ollama**, и отдаёт
по сети состояние машины: видеокарту, службу, загруженные модели, память,
процессор, диск и журнал.

Ставится по желанию. Без неё ollchat работает как прежде — просто не видит того,
чего в Ollama API нет.

## Зачем, если есть `/api/ps`

Часть данных видна по сети и без агента: `ollchat` сам считает долю модели
в видеопамяти по `size_vram / size` из `/api/ps` и по ней узнаёт вытеснение
в оперативную память. Агент нужен ради того, чего в API нет ни в каком виде:

| Что | Почему только с сервера |
|---|---|
| **Чужие процессы на карте** | Обучение чужим скриптом идёт мимо Ollama, а службу на это время обычно вовсе гасят. По сети карта выглядит свободной |
| **`OLLAMA_NUM_PARALLEL` и прочие переменные службы** | Число слотов не отдаётся ни одним запросом, а от него зависит, сколько запросов сервер обрабатывает разом |
| **Температура и троттлинг** | Карта под перегревом работает вдвое медленнее и выглядит просто «медленной» |
| **Журнал службы** | `model architecture does not currently support parallel requests`, ошибки CUDA, нехватка памяти, выгрузка модели |
| **Оперативная память и процессор хоста** | Вытесненные слои считает процессор — видно, сколько памяти держит сама Ollama |
| **Место под моделями** | Модель не загрузится, а причина будет выглядеть как сетевая ошибка |

## Что он умеет и чего не умеет

**Только чтение.** Список внешних команд зашит в коде (`nvidia-smi`,
`systemctl`, `journalctl`), и ни одна не принимает ничего из запроса. Служба
не умеет запускать модели, перезапускать Ollama, удалять файлы или менять
настройки — не по конфигурации, а по построению.

Ни алертов, ни базы, ни графиков, ни истории: для этого есть обычные системы
наблюдения. Здесь отвечают на четыре вопроса — свободна ли карта, не вытеснена
ли модель, сколько слотов у службы на самом деле и что она пишет в журнал.

## Установка

Собирается тем же тулчейном, что и остальной проект:

```bash
export PATH=$HOME/sdk/go1.26.5/bin:$PATH
go build -o ollnode ./ollnode
scp ollnode сервер:~/bin/
```

Запуск (токен обязателен — без него служба не стартует):

```bash
OLLNODE_TOKEN=$(openssl rand -hex 32) ollnode
```

Ключи:

| Ключ | По умолчанию | Что задаёт |
|---|---|---|
| `--listen` | `127.0.0.1:11435` | адрес и порт службы |
| `--ollama` | `http://127.0.0.1:11434` | адрес Ollama на этой же машине |
| `--service` | `ollama` | имя юнита systemd |
| `--models-dir` | из `OLLAMA_MODELS` | каталог моделей для проверки места |
| `--cache` | `5s` | сколько держать снимок в кэше |
| `--journal` | `15m` | за какое время смотреть журнал |
| `--util-samples` | `3` | сколько выборок загрузки карты брать |
| `--util-gap` | `1s` | шаг между выборками |
| `--journal-sudo` | нет | читать журнал через `sudo` |
| `--ours` | пусто | пути своих процессов на карте через запятую: то, что служба Ollama не запускала, но своё |

**`--ours` — зачем.** Свой процесс наблюдатель узнаёт по родству с главным
процессом службы Ollama (счётчики моделей — её дети). Но на карте бывает и своё,
запущенное мимо службы: у нас это реранкер `bge-reranker-v2-m3`, поднятый
контейнером llama.cpp, — он виден как `/app/llama-server` и службе не родня.
Без этого ключа он числится чужой работой, и клиент пишет «чужое на карте:
llama-server (1460 МиБ)». Поведения это не меняет (наблюдатель ни на что
не влияет с 12.09.2026), но строка врёт. Ключ принимает подстроки пути:

```
ollnode --listen 127.0.0.1:11435 --ours /app/llama-server
```

## Права

Служба работает под **непривилегированной** учётной записью:

- `nvidia-smi` доступен всем;
- `systemctl show` — тоже (это чтение);
- `journalctl -u ollama` требует членства в группе `systemd-journal`
  (`sudo usermod -aG systemd-journal <учётка>`) либо ключа `--journal-sudo`.

Чего не хватило — не пропадает молча: раздел приходит в `missing` с причиной.
Пустой раздел без причины означал бы «там ничего нет», а это разные вещи.

## Доступ по сети

**Порт наружу открывать не нужно.** По умолчанию служба слушает `127.0.0.1`,
и ollchat дотягивается до неё тем же туннелем ssh, которым ходит к Ollama:

```bash
ssh -N -L 11435:127.0.0.1:11435 сервер
```

Если всё же нужен отдельный адрес — `--listen 0.0.0.0:11435`, но тогда порт
должен быть закрыт снаружи брандмауэром. Токен проверяется всегда, но токен —
это последний рубеж, а не первый.

## Запросы

```bash
curl -H "Authorization: Bearer $OLLNODE_TOKEN" http://127.0.0.1:11435/api/v1/node
curl -H "Authorization: Bearer $OLLNODE_TOKEN" 'http://127.0.0.1:11435/api/v1/node?light=1'
curl http://127.0.0.1:11435/healthz
```

- `/api/v1/node` — снимок целиком.
- `?light=1` — без журнала и диска: этим опрашивают часто.
- `/healthz` — жива ли служба. Без токена и без сбора; ею пользуется systemd.

Снимок кэшируется (`--cache`): серия выборок `nvidia-smi` занимает секунды,
а спрашивают часто. Дешёвый снимок отдаётся из полного кэша, полный из
дешёвого — нет.

Пример ответа (сокращённо):


Загрузка карты — **наибольшая** выборка серии, а не последняя: одиночный снимок

«свободно» посреди чужой работы. Все выборки видны в `util_samples`.

## Юнит systemd

```ini
[Unit]
Description=ollnode — наблюдатель за Ollama
After=network-online.target

[Service]
Type=simple
User=ollnode
Environment=OLLNODE_TOKEN=длинная-случайная-строка
ExecStart=/home/ollnode/bin/ollnode --listen 127.0.0.1:11435 --ours /app/llama-server
Restart=on-failure
RestartSec=5
# Служба только читает — пусть и система это подтвердит.
ProtectSystem=strict
ProtectHome=read-only
PrivateTmp=true
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

Токен лучше держать не в самом юните, а в файле с правами `600`:
`EnvironmentFile=/etc/ollnode.env`.
