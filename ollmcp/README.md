# ollmcp — библиотека книг и граф понятий как служба MCP

Поиск по личной библиотеке и граф понятий доступны модели внутри `ollchat`. Но
это знание нужно и другим: другому ассистенту, скрипту, самому владельцу
из командной строки. `ollmcp` отдаёт их по протоколу MCP и **работает
независимо от того, запущен ollchat или нет** — как поисковая служба, к которой
ходят разные клиенты.

## Запуск

```bash
ollmcp                          # режим stdio: клиент запускает сервер сам
ollmcp --http 127.0.0.1:8377    # постоянная служба для нескольких клиентов
ollmcp --tools                  # какие инструменты есть, и выйти
ollmcp -v                       # писать обращения клиентов в поток ошибок
```

Настройки берутся из файла `ollchat`: где лежит база знаний, коллекция
по умолчанию, чем считать смыслы, адрес SearXNG. Своего файла настроек у службы
нет намеренно — иначе два файла разъедутся.

**В режиме stdio в стандартный вывод не пишется ничего, кроме ответов
протокола.** Любая посторонняя строка ломает разбор у клиента, поэтому все
пояснения уходят в поток ошибок.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `kb_search` | ищет по книгам, возвращает фрагменты со ссылкой на книгу и страницу |
| `kb_read` | читает найденный фрагмент вместе с соседними |
| `kb_status` | состав библиотеки: книги, фрагменты, смыслы, состояние графа |
| `graph_search` | ищет по графу понятий: понятия, связи и цитаты-подтверждения |
| `graph_entity` | карточка одного понятия: написания, охват, связи, где написано |
| `graph_path` | цепочка связей между двумя понятиями с подтверждением на шаге |
| `web_search` | поиск через свой SearXNG (только если задан `web.searxng_url`) |

Обзор тем по сообществам графа (`graph_overview`) и карточка одной темы (`graph_topic`)
отдаются службой наравне с остальными: список инструментов — `tools.ReadOnlyNames()`.

**Все инструменты только читают.** Сборки индекса, векторизации и построения
графа здесь нет и не будет: они занимают видеокарту на часы, и право запускать
их остаётся у человека командами `ollchat`. Это то же правило, по которому
у модели в самом `ollchat` нет инструмента сборки графа.

Список инструментов задан в коде (`readOnlyTools` в `tools.go`), а не берётся
из `agent.tools` настроек: в конфиге у агента включены `bash`, `write_file`
и `edit_file` — они нужны ему в рабочем каталоге, но служба, доступная
нескольким клиентам, ничего писать и запускать не должна.

## Подключение клиента

Клиент, умеющий stdio (так работает большинство):

```json
{
  "mcpServers": {
    "ollchat-kb": { "command": "/home/пользователь/bin/ollmcp" }
  }
}
```

Постоянная служба: сообщение JSON-RPC уходит телом `POST /mcp`, ответ приходит
телом ответа. Проверка живости — `GET /health`.

```bash
curl -s http://127.0.0.1:8377/mcp -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"kb_status","arguments":{}}}'
```

## Осторожно с адресом

**Проверки подлинности у службы нет.** Она отдаёт содержимое личной библиотеки
всякому, кто до неё дотянется. Поэтому по умолчанию слушать надо localhost,
а при другом адресе служба предупреждает об этом в поток ошибок. Нужен доступ
с других машин — заводите ssh-туннель, как это сделано для стенда.

## Юнит systemd

```ini
[Unit]
Description=ollmcp — библиотека книг как служба MCP
After=network.target

[Service]
ExecStart=/home/пользователь/bin/ollmcp --http 127.0.0.1:8377
Restart=on-failure
User=пользователь

[Install]
WantedBy=default.target
```

## Сборка

Только тулчейном проекта:

```bash
export PATH=$HOME/sdk/go1.26.5/bin:$PATH
go build -o ollmcp ./ollmcp
go test ./ollmcp/
```

## Ключ доступа для режима HTTP

Служба отдаёт содержимое личной библиотеки и, если настроен SearXNG, ходит в сеть.
На localhost этого достаточно, но как только она слушает не петлевой адрес, её видит
вся сеть.

Ключ задаётся **переменной окружения**, не флагом и не в конфиге:

```bash
OLLMCP_TOKEN=длинная-случайная-строка ollmcp --http 0.0.0.0:8377
```

Флаг виден в `ps` любому пользователю машины, а конфиг копируют и пересылают —
тем же соображением продиктовано хранение токена Confluence в ollchat.

Клиент шлёт ключ заголовком `Authorization: Bearer <ключ>` либо `X-Ollmcp-Token: <ключ>`.
Без ключа или с неверным — `401`, без подробностей: чем меньше сказано, тем меньше
подсказано. Сравнение постоянного времени, чтобы ключ нельзя было подобрать знак
за знаком по времени ответа.

Переменная не задана — проверки нет, и служба ведёт себя как прежде. Это сознательное
умолчание: на localhost ключ ни от чего не защищает, а требовать его там, где он не
нужен, значит приучать его отключать. При запуске служба пишет в журнал, с ключом
она работает или без, а при не-петлевом адресе без ключа предупреждает отдельно.

В юните systemd ключ задаётся строкой `Environment="OLLMCP_TOKEN=..."` — файл юнита
при этом должен быть закрыт от чужих глаз (`chmod 600`).
